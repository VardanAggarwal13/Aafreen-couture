# Performance audit (source-level) - aafreencouture.com

## HIGH
1. src/app/page.tsx (no `export const revalidate`): home is async server components hitting DB (NewArrivals/BestSellers via productService). Without revalidate it is frozen at build time unless admin calls revalidatePath. Fix: add `export const revalidate = 120;` (matches shop pages).
2. src/features/product/components/ProductDetailClient.tsx:243-250 and :901-906: gallery renders ALL images with `unoptimized` (full-size originals, bypasses Cloudinary loader) and lightbox image also `priority unoptimized`. Fix: remove `unoptimized` (loader handles Cloudinary); lazy-render only selected + neighbour images; drop `priority` at :905 (lightbox).
3. src/features/home/components/HeroSection.tsx:1,34-40 + layout.tsx: whole hero is 'use client' just for framer-motion; h1 starts opacity:0 so LCP candidate (h1 on mobile / text) is delayed by 0.22s delay + 0.7s fade + hydration; framer-motion ships in the home critical bundle. Image LCP itself is OK (priority, fill, sizes=100vw) but quality/size: Cloudinary loader w_ up to 2048 for a 100vw hero. Fix: make HeroSection a server component, replace motion.* with CSS keyframes (`animate-in fade-in slide-in-from-bottom-3` from tw-animate-css, `animation-delay`), keep h1 visible (opacity-100, animate only transform) or animate only non-LCP items. Keep scroll-indicator as CSS `animate-pulse`. Add `fetchPriority="high"` on hero Image. Use `sizes="100vw"` is fine.

## MEDIUM
4. src/components/product/ProductCard.tsx:49-60: `quality={95}` on both primary and secondary image (loader maps >=90 to q_auto:best -> heavy bytes on every grid card). Fix: quality 75 (default), card grids on 50vw mobile. Secondary hover image is fetched when card enters viewport; render it only on hover/`loading="lazy"` + `fetchPriority="low"` or skip on touch.
5. Too many priority images: ProductCard priority={i<4} in NewArrivals/BestSellers/ShopClientPage/CoutureCatalogView (below hero on home: NewArrivals.tsx:64, BestSellers.tsx:64 = 8 competing preloads with hero). Fix: remove priority from home NewArrivals/BestSellers (below fold); on listings keep i<2 only (mobile 2-col). collections/[slug]/page.tsx:186,230,239 and occasions/page.tsx:174 have priority on mutually exclusive branches (OK); Navbar.tsx:124 logo priority is fine, but Navbar.tsx:365 (mobile drawer logo, hidden) priority forces a needless preload - remove it.
6. src/components/layout/Navbar.tsx (650 lines, 'use client', useSession + authClient + router.prefetch x29 incl. on mount lines 65-69): site-wide on every page; session fetch on mount triggers extra request, prefetches contend with LCP. Fix: split into server shell + small client islands (account menu, mobile drawer, search); prefetch only on hover/idle (requestIdleCallback); lazy-load drawer and SearchOverlay with next/dynamic.
7. Home sections: src/features/home/components/Testimonials.tsx 'use client' (carousel + filter, ~large static data); lazy-load via next/dynamic (below fold) or make list server-rendered with a small client carousel.
8. Providers (src/providers/Providers.tsx): wraps entire site with QueryClientProvider + ThemeProvider + TooltipProvider + Toaster; theme is light-only (enableSystem false) so next-themes adds an inline script/overhead for nothing. Fix: remove ThemeProvider (pass `theme="light"` to Toaster), mount Toaster via next/dynamic ssr:false, move QueryClientProvider to only the segments using useQuery (Navbar, SearchOverlay, shop, cart, wishlist - Navbar uses it, so lazy-load query provider where possible). Devtools import is a static top-level import: guarded by NODE_ENV so tree-shaken in prod, acceptable, but safer: `dynamic(() => import(...), {ssr:false})`. Also Providers.tsx:33 references nonexistent `--font-montserrat` -> toasts fall back to sans-serif; use `var(--font-jakarta)`.
9. Third-party scripts: GoogleAnalytics.tsx:30-45 and MetaPixel.tsx:30-50 use strategy="afterInteractive" in root layout: ok but both load on every page right after hydration and compete with INP/LCP on slow phones. Fix: `strategy="lazyOnload"` for Meta Pixel (and GA if acceptable), or use `@next/third-parties/google` GoogleAnalytics. Add `<link rel="preconnect" href="https://res.cloudinary.com" crossOrigin>` in layout <head> (none present; hero LCP image lives on Cloudinary - saves ~100-300ms). CSP script-src lacks https://www.googletagmanager.com and connect-src lacks google-analytics/analytics domains (next.config.ts:67-72) - GA is blocked in prod (functional bug).
10. Caching headers (next.config.ts:87-94): /images/* max-age=86400 only; logos/static imagery are not hashed. Acceptable but use `max-age=2592000, stale-while-revalidate=86400` or hash filenames. /fonts, favicon not covered (next/font self-hosts under _next/static: already immutable).

## LOW
11. Unused deps (0 imports in src/): `next-cloudinary`, `@react-email/components`, `react-email` (move to devDeps if emails use them via resend; grep found none), `shadcn` (only CSS import `shadcn/tailwind.css` -> keep as devDependency), `@tanstack/react-query-devtools` -> devDependencies. Remove next-cloudinary (also dead since custom loader).
12. CLS: Hero uses fixed vh height, ProductCard uses aspect-[9/16], logos have width/height - good. Risks: fonts use `display:'swap'` with 5 weights x2 styles Cormorant (+italic) - reduce weights to 400/500/600 and italic only if used (fewer font files; also `adjustFontFallback` is default so swap CLS minimal). Home skeletons (NewArrivals ProductCardSkeleton) fine. Sticky navbar `backdrop-blur-md` + bg-navbar/95 causes repaint cost on scroll (INP/scroll jank on low-end); use solid bg.
13. Middleware matcher (src/middleware.ts) runs on all page requests incl. static pages (cheap, cookie check only). OK; add `sitemap.xml|robots.txt` exclusions.
14. 62 files use 'use client'; candidates to convert/split: HeroSection (high), Testimonials, Navbar shell, CategoryHubView/CoutureCatalogView (listing grids: server-render product grid, keep filters client), ProductDetailClient (955 lines - split gallery/lightbox/reviews, dynamic-import lightbox at :732).
